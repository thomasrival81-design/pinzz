# PINZX — Clean Rebuilt Base

This is a new Flutter app source tree. It does not copy the old app's Dart modules, Android package tree, remote-control code, or attack modules. Only the supplied PINZX logo and intro video are reused as assets. The screen flow is:

1. Long-press fingerprint progress (0–100%)
2. PINZX landing page + GET STARTED NOW
3. Login against the PINZX Auth API
4. Intro video with progress indicator + SKIP
5. New PINZX dashboard (preview-only cards)

Owner/developer branding: **Valltyyy / @Valltyyy**.

## Flutter setup

Install Flutter (Dart 3.3+), then in this folder run:

```sh
flutter create --project-name pinzx --platforms=android .
flutter pub get
```

Set the API URL at build time once the API is deployed:

```sh
flutter run --dart-define=PINZX_API_URL=https://YOUR_REAL_API_DOMAIN
flutter build apk --release --dart-define=PINZX_API_URL=https://YOUR_REAL_API_DOMAIN
```

Do not use plain HTTP in production. The default placeholder intentionally fails closed until you configure the real HTTPS URL.

## API setup

```sh
cd api
npm install
cp .env.example .env
```

Set a unique `JWT_SECRET`, admin username, and bcrypt password hash in `.env`, then run `npm start`. Put it behind HTTPS using a trusted reverse proxy/hosting platform. The API currently implements only `/health` and `/auth/login`; it does not expose attack, DDoS, crash, or remote-control endpoints.

## Notes

- The client stores only the short-lived auth token using `flutter_secure_storage`; it does not persist the password.
- The included backend example seeds one administrator via environment variables; it is not a full user-management system.
- No APK is included: this bundle is clean source code, and the Android project files are generated by `flutter create` on a machine with Flutter installed.
